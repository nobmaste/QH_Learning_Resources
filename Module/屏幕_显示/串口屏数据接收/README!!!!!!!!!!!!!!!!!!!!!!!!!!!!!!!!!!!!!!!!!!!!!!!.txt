如果需要使用的话修改教程如下（仅提供.c文件的修改思路，.h文件看情况更新就行）

修改typedef enum
理论上来说，除了帧头和帧尾都可以删掉。中间的数据帧按需添加。

串口屏发送不定长数据建议定义为
printh 帧头
printh 数据长度
printh 数据内容
printh 帧尾

修改uint8_t全局变量
这里定义你需要的状态机状态

修改数据处理函数
定义接收完数据后如何处理

修改parse_byte
 state变量存放状态。parse_ byte每次读取一个数据，用switch函数来载入处理流程
大致流程be like：
识别帧头-->（接收到了帧头）更新状态机为等待数据状态-->如果在该状态下接收到了正确数据，存放数据到全局变量，更新状态机状态（比方说等待下一个数据）；如果在该状态下没有接受到正确数据，重置状态为识别帧头状态。可以在这里做数据类型判别等需要的功能-->经过一连串所需状态-->识别帧尾-->完成一帧的数据接收，转入数据处理函数，并且重置状态机为识别帧头状态

修改之前一定要先设计好你上位机数据发送逻辑，帧头是什么，帧尾是什么，中间发送的数据是什么，怎么处理。
一般的话数据可以这样设计“帧头+数据长度+数据内容+帧尾"
用来接受不定长的数据，这个时候用两个变量分别取存放数据长度和数据内容，用于存放数据内容的一般用数组，初始化长度设置大一点。数据长度作为循环判断标准，通过循环来向数组写入数据，最后在结尾补充结束符

        // ---- 数据接收 ----
        case WAIT_DATA:
            data_buf[data_index++] = byte;
            if (data_index >= data_len) {
                data_buf[data_len] = '\0';    // 补充字符串结束符
                state = WAIT_FF1;
            }
            break;

这个时候状态机流程为“等待帧头->读取数据长度->读取数据内容并存放到对应的数组->识别帧尾”

也可以按需增加，如“帧头+数据类型+数据长度+数据内容+帧尾”
状态机流程为
等待帧头->读取数据类型->读取数据长度->读取数据内容并存放到对应的数组->识别帧尾”
并且增加对应的数据处理函数
